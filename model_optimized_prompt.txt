QUESTION TYPE RULES
- single_select: exactly 1 dataset var
- numeric: exactly 1 dataset var
- open_text: exactly 1 dataset var
- multi_select: list of dataset vars
- grid / numeric_grid:
  - vars is list of lists
  - each inner list is one ROW containing dataset vars across columns
  - preserve questionnaire row order (reorder if dataset storage differs)

LOGIC DECISION TREE (USE IN THIS ORDER)
1) If rule determines whether a question is asked -> type="skip"
2) Else if rule enforces none/DK/RF non-cooccurrence -> type="exclusive"
3) Else if rule enforces min/max/exactly number selected -> type="count"
4) Else if rule enforces arithmetic total/add-up -> type="sum"
5) Else if rule filters/carries forward downstream answer options -> type="piping"
6) Else if rule is deterministic derived transformation -> type="recode"
7) Else -> type="custom"

LOGIC DEFINITIONS (SINGLE SOURCE OF TRUTH)

A) skip
- Meaning: current target question is not asked when condition is TRUE.
- Placement: only on target question(s) being skipped.
- source_vars: gating vars in condition.
- target_vars: must equal current question vars.
- Condition semantics: TRUE => skip current target question.
- For ask-if rules: invert ask-if into skip condition.

B) exclusive
- Meaning: exclusive option(s) cannot co-occur with non-exclusive options in same multi-select.
- Placement: on that multi-select question.
- source_vars: full option set for that question.
- target_vars: exclusive anchor var(s) only (often *_97/*_98/*_99 or none/DK/RF option vars).

C) count
- Meaning: min/max/exactly constraints on number selected.
- source_vars: vars being counted.
- target_vars: current question vars.
- Only type allowed for min/max/exactly.

D) sum
- Meaning: sum/add-up constraints.
- source_vars: vars in the sum (+ total var if referenced).
- target_vars: current question vars.

E) piping
- Meaning: answer-option filtering/carry-forward/elimination in downstream question.
- Placement: on downstream filtered question.
- source_vars: upstream selector vars.
- target_vars: downstream answer option vars filtered by source selections.
- Piping is answer-level only (no text piping).
- In most funnels source_vars and target_vars are same-size aligned lists (1:1); non-1:1 allowed if condition still boolean and valid.

F) recode
- Meaning: deterministic derived-variable transformation.
- source_vars: inputs used to derive.
- target_vars: derived var(s) assigned/used.
- Derived variable must exist in derived_variables.

G) custom
- Meaning: valid rule not representable by other six.
- source_vars: vars referenced.
- target_vars: affected vars for current question.

ROUTING EXPANSION (CANONICAL, MANDATORY)
Use questionnaire order from PDF and expand every route deterministically:

1) Skip-to-question
- For “if X then skip to Qk”:
  - identify source index and Qk index.
  - every question strictly between them is a skipped target.
  - add skip logic to EACH skipped target question (not source).
  - source_vars = vars in X; target_vars = that target question vars.

2) Skip-to-section
- For “if X then skip to Section S”:
  - identify first question of Section S.
  - every question strictly between source and first question of Section S is a skipped target.
  - add skip logic to EACH skipped target question.

3) Section eligibility gates
- If entry to a section is conditional:
  - add skip logic to EVERY question in that section using inverted eligibility.

4) Validation of routing expansion
- No routing instruction may remain unexpanded.
- No skip logic on source question unless that source question is itself a downstream target of another gate.
- For every skip logic, target_vars must equal current question vars.
- For each skip-to-section instruction, the number of generated target skip entries must equal the number of in-between questions skipped before the destination section starts.
